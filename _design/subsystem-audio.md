# SUBSYSTEM: audio

## Summary
A single AudioContext drives a fixed bus topology: every voice routes into one of five category GainNodes (sfx, granny, heartbeat, ambient, ui), each feeding a master GainNode → DynamicsCompressorNode → destination. The context starts suspended; a one-time user-gesture handler (pointerlock click) calls ctx.resume() and primes a silent buffer to unlock iOS/Safari. 3D sound uses one AudioListener kept in sync with the Three.js camera every frame (position + forward/up via setPosition/setOrientation, or the AudioParam form with setTargetAtTime for click-free updates); spatial voices route through a PannerNode (HRTF, inverse distance). Every sound is synthesized on demand from OscillatorNode / AudioBufferSourceNode(noise) / BiquadFilterNode / WaveShaperNode chains with explicit GainNode ADSR envelopes scheduled on the context clock. Occlusion is approximated per-spatial-voice by inserting a per-voice lowpass biquad whose frequency and an extra gain are driven by a physics raycast from Granny to the listener (clear = 20 kHz/0 dB, occluded = 700 Hz/−9 dB), smoothed with setTargetAtTime. Granny's vocalizations are a state machine of looping layers (breathing+humming when idle/patrol, muttering when searching, growl/scream stings on detection/chase). Heartbeat is a self-scheduling two-thump synth whose rate and gain are a continuous function of a 0..1 intensity set from proximity+awareness. A jumpscare sting on capture ducks all other buses and fires a layered noise+detuned-cluster hit.

## Key Decisions
- ONE AudioContext for the whole game, created lazily inside the unlock gesture (never at module load — a context created before a gesture starts 'suspended' and Chrome/Safari may forbid resume from a non-gesture path). Store it on a singleton AudioEngine.
- Five category buses (sfx, granny, heartbeat, ambient, ui) each a GainNode → masterGain → DynamicsCompressorNode(limiter) → ctx.destination. This gives independent volume sliders, lets the jumpscare duck non-jumpscare buses in one place, and the compressor prevents clipping when many voices stack (heartbeat + growl + slam simultaneously).
- Spatial vs non-spatial split: positional sounds (footsteps, Granny, doors, items, wood-break) go voice→PannerNode→categoryBus; non-positional sounds (heartbeat, UI, the master house drone, the jumpscare sting) go voice→categoryBus directly. Never panner-ize the heartbeat or UI — they are 'inside the player's head'.
- Synthesize-and-discard, not preload-and-replay. Each playSfx() builds a fresh node graph, schedules its envelope, sets node.onended to disconnect every node, and returns a handle. Web Audio nodes are cheap; reusing source nodes is illegal (a started AudioBufferSourceNode/Oscillator cannot be restarted).
- One shared, pre-generated noise AudioBuffer (2 s, mono, white) reused by all noise-based voices via fresh AudioBufferSourceNode each time. Generating noise per-shot is wasteful; generating the buffer once at unlock is correct.
- Occlusion is an approximation living on the spatial voice graph, not a real acoustic sim: a single lowpass biquad + makeup gain per long-lived spatial source (Granny especially), updated from the existing cannon-es raycast the AI already does. Do NOT raycast per footstep — only persistent sources need live occlusion.
- Granny audio is a layered loop manager driven by her AI state enum, decoupled from one-shot stings. Loops crossfade over 300–600 ms on state change so transitions never click or hard-cut.
- All parameter changes that could click (gain steps, filter sweeps, listener moves, occlusion) use setTargetAtTime / linear|exponentialRampToValueAtTime, never direct .value = assignments during playback.

## Data Model
AudioEngine singleton owns: ctx:AudioContext|null; unlocked:boolean; masterGain, limiter(DynamicsCompressorNode); buses:{sfx,granny,heartbeat,ambient,ui}:GainNode; listener:AudioListener (=ctx.listener); noiseBuffer:AudioBuffer (2s white); volumes:{master,sfx,granny,heartbeat,ambient,ui}; activeVoices:Set<Voice> (for global stop/duck). Heartbeat state: {intensity:0..1, running:boolean, nextBeatTime:number, schedulerId}. GrannyAudio state: {state:'idle'|'patrol'|'search'|'chase'|'stunned', layers:{breath:LoopVoice, hum:LoopVoice, mutter:LoopVoice}, currentTargetGains}. Occlusion per spatial Voice: {panner:PannerNode, occludeLP:BiquadFilterNode, occludeGain:GainNode, occluded:boolean}. A Voice handle = {nodes:Node[], output:AudioNode, panner?:PannerNode, stop(when?), setPosition(x,y,z)}. Footstep config table keyed by surface: {wood,carpet,tile,concrete,metal,creakyboard} each → {noiseColorHz, bodyFreqHz, decayMs, clickGain, lowpassQ}.

## Public Interface
- AudioEngine.init(): void — attaches a one-time pointerdown/click+keydown listener on document that lazily creates ctx, builds the bus graph, generates noiseBuffer, calls ctx.resume(), plays a 1-sample silent buffer to unlock, sets unlocked=true. Idempotent.
- AudioEngine.playSfx(name:string, position?:{x,y,z}|THREE.Vector3, opts?:{volume?=1, rate?=1, detune?=0, surface?:string, occluder?:()=>boolean, loop?=false}): Voice|null — looks up the synth recipe by name, builds graph, if position given inserts PannerNode at that position (+ occlusion chain when occluder provided), schedules envelope, auto-disconnects on end. Returns a Voice handle (null if not unlocked). Names: 'footstep','door_creak','door_slam','item_pickup','item_drop','wood_break','ui_click','ui_hover','ui_back','jumpscare'.
- AudioEngine.setListener(camera:THREE.Camera): void — call once per frame in the render loop; copies camera world position + forward/up into ctx.listener using setTargetAtTime ramps (timeConstant 0.02 s) so fast camera turns don't zipper.
- AudioEngine.setHeartbeat(intensity:number /*0..1*/): void — clamps, ramps the internal intensity over 250 ms; starts the self-scheduling beat loop if intensity>0.02, stops it (fade 400 ms) when it returns to ~0. Rate and loudness derived from intensity (see algorithms).
- AudioEngine.granny.setState(state, grannyPos:Vector3): void — drives the looping vocal layers; crossfades layer gains to the target mix for the new state over 400 ms; fires associated one-shot sting ('growl' on idle→chase/search→chase, 'scream' on first chase spot, 'whimper' on stunned).
- AudioEngine.granny.update(grannyPos, dt): void — per-frame; moves the granny loop panner to grannyPos and updates occlusion (lowpass+gain) from the LOS raycast result the AI provides.
- AudioEngine.setBusVolume(bus:string, v:number): void and AudioEngine.duck(exceptBus, toGain, attackMs, holdMs, releaseMs): void — duck is used by the jumpscare.
- AudioEngine.stopAll(fadeMs=60): void — for pause/menu/teardown.

## Tunables
- ctx.sampleRate = 44100 Hz (browser default; do not force 48000 — let the device decide)
- masterGain.gain = 0.9 (headroom below the limiter)
- limiter (DynamicsCompressor): threshold=-6 dB, knee=6 dB, ratio=12, attack=0.003 s, release=0.25 s
- bus default gains: sfx=0.9, granny=1.0, heartbeat=0.7, ambient=0.5, ui=0.6
- PannerNode: panningModel='HRTF', distanceModel='inverse', refDistance=1.0 m, maxDistance=35 m, rolloffFactor=1.4, coneInnerAngle=360 (omni for most), Granny voice cone: inner=120°/outer=300°/outerGain=0.4
- listener sync timeConstant = 0.02 s (setTargetAtTime)
- Footstep walk cadence = 0.55 s/step; sprint = 0.34 s/step; crouch = 0.85 s/step. Per-step random rate jitter ±6%, gain jitter ±12%
- Footstep envelope: attack 1 ms, decay 60–140 ms by surface (wood 90, carpet 60, tile 110, concrete 100, metal 140, creakyboard 130 + creak sub-layer)
- Heartbeat: BPM = 50 + intensity*90 → range 50–140 BPM; thump gain = 0.25 + intensity*0.75; lub-dub gap = 0.16 s; each thump 60–90 Hz sine, attack 4 ms / decay 120 ms; sub-rumble 35 Hz added when intensity>0.6
- Granny breathing loop: period 3.2 s (inhale 1.2 s / exhale 1.6 s / pause 0.4 s), bandpassed noise 300–900 Hz
- Granny hum: fundamental wander 130–175 Hz, vibrato 5 Hz ±8 cents, gain 0.18
- Granny growl sting: 1.1 s, 70–110 Hz sawtooth cluster + waveshaper drive, gain 0.9
- Granny scream sting: 1.6 s, 420→900 Hz formant sweep + harsh noise, gain 1.0
- Occlusion: clear = lowpass 20000 Hz & occludeGain 1.0 (0 dB); occluded = lowpass 700 Hz & occludeGain 0.35 (−9 dB); transition setTargetAtTime timeConstant 0.08 s
- Door creak: 0.8–1.6 s pitch-rising friction (resonant bandpass on noise, center 400→1200 Hz); slam: 1 ms attack noise burst + 80 Hz body thud, total 350 ms, gain 0.95
- Wood break: 0.5 s, 3–5 stacked short noise cracks (10–25 ms each) + 120 Hz snap body
- Jumpscare sting: 1.8 s; duck other buses to 0.15 over 30 ms, hold 1.2 s, release 600 ms
- UI click: 1200 Hz square blip, 40 ms, gain 0.3; hover: 2000 Hz sine, 25 ms, gain 0.15; back: 600 Hz, 60 ms

## Algorithms
- UNLOCK: on first document pointerdown/keydown → if !ctx create AudioContext; build masterGain→limiter→destination, then each bus GainNode→masterGain; generate noiseBuffer (fill Float32Array length sampleRate*2 with Math.random()*2-1); ctx.resume(); create a 1-frame silent AudioBufferSource, connect→destination, start() (Safari unlock); set unlocked=true; remove listeners. All later playSfx before this return null safely.
- PER-FRAME LISTENER SYNC: read camera.getWorldPosition(p) and camera.getWorldDirection(f); up = camera.up transformed. If listener.positionX exists use positionX.setTargetAtTime(p.x, ctx.currentTime, 0.02) for x/y/z and forwardX/Y/Z + upX/Y/Z; else fall back to listener.setPosition/ setOrientation. Doing this with setTargetAtTime prevents the Doppler 'zipper' on fast 180° turns.
- SPATIAL VOICE BUILD: src→[envelopeGain]→(if occluder)[occludeLP→occludeGain]→panner→bus. Set panner.positionX/Y/Z to the world position (ramp if it's a moving source). For one-shots, panner position is set once. node.onended disconnects the whole chain.
- FOOTSTEP SYNTH: pick surface config. Layer A = noise burst: AudioBufferSource(noiseBuffer, loop, random offset)→bandpass(center=bodyFreqHz, Q=lowpassQ)→gain(env: 0→1 in 1ms, →0 exp over decayMs). Layer B = body 'thud': sine at bodyFreqHz (wood~180, carpet~120, tile~250, concrete~150, metal~300)→gain env decay*0.6. creakyboard adds Layer C = short resonant bandpass sweep 300→700 Hz over 180 ms at 0.15 gain, fired ~20% of steps. Apply per-step rate/gain jitter. Footsteps ALSO emit a hearing noise-event to the AI (decoupled from audio gain).
- HEARTBEAT SCHEDULER: a setTimeout/look-ahead loop (25 ms tick, schedule-ahead 100 ms) computes beatInterval=60/BPM. At each nextBeatTime schedule a 'lub' (sine f0=70Hz, gain env attack 4ms decay 120ms) and a 'dub' at +0.16 s (sine 60Hz, slightly quieter). When intensity>0.6 add a 35 Hz sub sine on the lub. nextBeatTime += beatInterval. Rate & gain read the smoothed intensity each beat so changes are musical, not abrupt. On setHeartbeat(0) ramp heartbeat bus to 0 over 400 ms then stop scheduler.
- GRANNY LOOP MIX: maintain 3 persistent looping voices (breath, hum, mutter) all routed through one shared granny panner+occlusion chain (so occlusion applies to all her vocals at once). State→target gain matrix: idle{breath .5,hum .25,mutter 0}, patrol{breath .6,hum .35,mutter 0}, search{breath .7,hum .1,mutter .5}, chase{breath 1.0,hum 0,mutter .2}, stunned{breath .9 slow,hum 0,mutter 0}. On setState ramp each layer gain to target over 400 ms (linearRamp) and fire the transition sting.
- GROWL STING SYNTH: 3 detuned sawtooth osc (70,82,110 Hz, detune ±15 cents)→summing gain→WaveShaper(tanh drive curve, 256 samples)→lowpass(900Hz, Q1)→env(attack 30ms, sustain 0.7s at gain .9, release 300ms). Routed through granny panner so it's spatial. SCREAM: sawtooth 420 Hz with frequency.linearRampToValueAtTime(900, +0.6s) + bandpass formants (700/1100/2600 Hz) + white-noise layer (highpass 1.5kHz, gain .3); env attack 8ms, 1.3s body, release 300ms; gain 1.0.
- OCCLUSION UPDATE (per frame for Granny): AI provides occluded:boolean from a cannon-es ray Granny→listener hitting world geometry. occludeLP.frequency.setTargetAtTime(occluded?700:20000, t, 0.08); occludeGain.gain.setTargetAtTime(occluded?0.35:1.0, t, 0.08). Optionally lerp by ray-fraction for partial occlusion. This makes Granny sound muffled-and-quieter through a wall, sharp-and-loud in the open — the core stealth audio cue.
- DOOR CREAK: AudioBufferSource(noise)→bandpass(center.linearRamp 400→1200 over duration, Q=12 for a 'singing' resonance)→gain(slow attack 50ms, irregular amplitude via a 7 Hz LFO gain*0.4)→panner at door hinge. Tie duration to the hinge constraint's angular speed: faster swing = shorter/higher creak. SLAM: noise burst (attack 1ms decay 80ms, highpass 1.5kHz for the 'crack') + 80 Hz sine thud (decay 250ms) summed; gain scales with door angular velocity at contact; emits a LOUD hearing event.
- JUMPSCARE: duck(exceptBus='ui', toGain 0.15, attack 30ms, hold 1.2s, release 600ms) on sfx/granny/heartbeat/ambient buses; simultaneously play a non-spatial sting: detuned osc cluster (110,113,220,440 Hz saw)→waveshaper→ + full-band noise burst (gain env attack 2ms decay 1.2s) + a 40 Hz sub→ all into sfx bus at gain 1.0. Stop the heartbeat scheduler at the climax.
- NON-SPATIAL one-shots (UI): osc→gain env→ui bus, no panner. Keep them dry and instant.

## Pitfalls
- Creating AudioContext at module load: it starts 'suspended' and resume() outside a user gesture is blocked → total silence. FIX: lazily create + resume ONLY inside the first pointerdown/keydown handler; gate all playSfx on unlocked.
- Forgetting the silent-buffer prime on iOS/Safari: ctx.resume() alone often isn't enough; first sound is dropped. FIX: start a 1-frame silent AudioBufferSource in the unlock gesture.
- Restarting a started node: OscillatorNode/AudioBufferSourceNode are one-shot; calling start() twice throws InvalidStateError. FIX: build a fresh node per playSfx; never cache+reuse source nodes (you CAN cache the AudioBuffer).
- Node leak / GC stall: not disconnecting finished voices keeps the graph growing → CPU climb and eventual crackle. FIX: set node.onended on the source to disconnect every node in the chain and remove the Voice from activeVoices.
- Setting .gain.value or .frequency.value directly during playback: produces audible clicks/zipper. FIX: always use setTargetAtTime / linear|exponentialRampToValueAtTime; for exponential ramps never target exactly 0 (use 0.0001).
- Doppler zipper on camera turns: snapping listener orientation each frame artifacts. FIX: ramp listener params with timeConstant ~0.02 s; consider panner.setPosition only on real movement.
- Per-footstep raycast for occlusion: thousands of rays/min tanks the physics step. FIX: occlusion only on persistent sources (Granny); footsteps just use distance attenuation via panner.
- Heartbeat scheduled with naive setInterval(playBeat): timer drift + tab-throttle desync → arrhythmia. FIX: look-ahead scheduler that schedules beats on ctx.currentTime, decoupled from the JS timer accuracy.
- exponentialRampToValueAtTime to 0 throws / silences: it's mathematically invalid. FIX: ramp to 0.0001 then a final setValueAtTime(0).
- Panner refDistance=0 or maxDistance<refDistance: NaN gain / silent or full-blast sound. FIX: refDistance=1, maxDistance=35, rolloffFactor>0.
- Stacking many loud voices clips harshly (slam + growl + heartbeat + scream): FIX the master DynamicsCompressor as a brickwall-ish limiter (ratio 12, threshold −6, fast attack).
- Granny loops audible from across the map because they never attenuate: FIX route ALL her vocal layers through the single granny panner so distance + occlusion apply uniformly; don't connect any granny layer straight to the bus.
- Tab backgrounded: timers throttle and ctx may suspend → sounds pile up or stop. FIX: on visibilitychange hidden → ctx.suspend()+pause heartbeat scheduler; visible → resume.
- UI/heartbeat accidentally spatialized making them quiet/off-center. FIX: explicitly route non-diegetic sounds with NO panner straight to their bus.

## Risks
- CPU: HRTF panning is more expensive than equalpower; with many simultaneous spatial voices (footsteps + Granny + doors) frame audio cost can rise. Mitigation: HRTF only for Granny + key sources, equalpower ('panningModel'='equalpower') for transient footsteps/items; cap concurrent footstep voices.
- Procedural realism ceiling: synthesized footsteps/voice can sound 'synthy' rather than organic. Mitigation budget time on noise-color + multi-layer + per-shot jitter + light waveshaping; the muttering/breathing layers carry most of the dread.
- Web Audio API surface differences: older Safari uses listener.setPosition/setOrientation (deprecated elsewhere) and lacks AudioParam form. Mitigation: feature-detect listener.positionX and branch.
- Mobile autoplay/suspension quirks beyond the unlock gesture (audio focus loss on calls/notifications) can leave ctx suspended. Mitigation: visibilitychange + a periodic ctx.state check that re-resumes after a gesture.
- Occlusion approximation can feel binary/poppy if state flips rapidly at wall edges. Mitigation: smooth with setTargetAtTime 0.08 s and optionally use the ray hit-fraction for partial values + hysteresis on the boolean.
- Tuning interdependence: heartbeat intensity must be fed a sane proximity+awareness function from gameplay; if that signal is noisy the heartbeat thrashes. Mitigation: the 250 ms internal ramp on intensity plus clamping smooths upstream noise, but gameplay should still low-pass its danger signal.

## CRITIQUE (worksProbability=0.55)
Verdict: Strong, knowledgeable design that gets the hard Web Audio gotchas right (lazy context, silent-buffer unlock, synthesize-and-discard, look-ahead heartbeat scheduler, ramp-don't-assign). It will produce sound and won't crash. BUT it WILL NOT be tense or fun as written, and several integration details are hand-waved that cause real bugs: a broken occlusion topology for one-shots, an under-specified intensity signal that makes the heartbeat the whole emotional payload yet leaves it ungoverned, a node-leak risk on looping voices that onended never fires for, and a listener-orientation math bug that will rotate the entire 3D field incorrectly. The PannerNode HRTF + per-frame setTargetAtTime on six listener params is also a real CPU/quality trap on integrated builds. Approve only after the fixes below; ~45% chance it ships fun-and-correct on first integrated build without them.

### Fatal Flaws
- LISTENER ORIENTATION MATH IS UNDERSPECIFIED AND WILL BE WRONG. The design says 'up = camera.up transformed' and uses camera.getWorldDirection(f) for forward. WebAudio's listener forward must be the direction the camera LOOKS (−Z in view space, which getWorldDirection gives, OK) but the UP vector must be the camera's WORLD up, i.e. (0,1,0) rotated by the camera's world quaternion — NOT camera.up (which in Three.js is a fixed local hint vector, default (0,1,0), and does NOT track pitch/roll). A first-person camera that pitches up/down to look at Granny on stairs will feed a stale up vector; forward and up become non-orthogonal and the HRTF field tilts/collapses. This is the single most likely 'audio sounds wrong and nobody knows why' bug.
- OCCLUSION TOPOLOGY IS BROKEN FOR ONE-SHOTS AND THE GRANNY-SHARED-PANNER CLAIM CONTRADICTS THE STING ROUTING. The design says occlusion is 'only on persistent sources (Granny)' and that ALL granny vocals route through ONE shared panner+occlusion chain. But it also says the growl/scream stings are built fresh per playSfx() and 'routed through granny panner so it's spatial.' A freshly-built one-shot node cannot be connected into a single shared panner that is already fed by 3 looping layers without (a) summing into that panner's input (fine) but then (b) the sting inherits whatever occlusion state the loop chain has, which is correct ONLY if the sting connects AFTER occludeGain. As written ('src→envelopeGain→occludeLP→occludeGain→panner') each voice builds its OWN occlusion chain, so stings get a private occlusion chain that is never updated by granny.update() (which only touches the persistent chain). Result: a scream through a wall plays full-bright/full-volume while her breathing is muffled — jarring and breaks the core stealth cue. The two routing statements are mutually inconsistent.
- THE HEARTBEAT IS THE ENTIRE EMOTIONAL PAYLOAD AND ITS INPUT SIGNAL IS HAND-WAVED. setHeartbeat(intensity) is 'a continuous function of proximity+awareness' — but that function is never defined, and the risks section admits 'if that signal is noisy the heartbeat thrashes' then waves it off with a 250ms ramp. 250ms is FAR too fast to hide a danger signal that updates per-frame from a noisy proximity+awareness blend; the heartbeat will surge and drop every time Granny ducks behind a doorframe or the awareness meter jitters. A thrashing heartbeat is actively un-tense — it reads as a bug, not dread. This is the 'will not be fun' core failure: tension comes from a heartbeat that RISES and STAYS UP through a chase and decays SLOWLY after you break line of sight, not one that tracks instantaneous proximity.
- LOOPING VOICES LEAK AND/OR NEVER STOP CLEANLY. The cleanup contract is 'node.onended disconnects the chain.' onended fires when a source reaches its scheduled end OR is stop()'d. For loop:true voices (granny breath/hum/mutter, the shared noise loops) onended NEVER fires until you explicitly stop() them. The design's stopAll/state-change crossfade ramps GAIN to 0 but the spec never says it calls source.stop() after the fade — so the oscillators/buffersources keep running silently forever, accumulating across granny state transitions and across a full play session. Combined with 'synthesize-and-discard' for stings every footstep/door, a 20-minute session leaks dozens of live-but-silent looping graphs. CPU climbs, then crackle, exactly the pitfall they claim to have solved for one-shots but reintroduced for loops.

### Concrete Fixes
- Listener up-vector: compute up correctly as camWorldQuaternion applied to (0,1,0). Per frame: camera.getWorldDirection(fwd); up.set(0,1,0).applyQuaternion(camera.getWorldQuaternion(q)); then feed forwardX/Y/Z=fwd, upX/Y/Z=up. Re-orthonormalize is unnecessary if you derive both from the same quaternion (getWorldDirection is already quaternion-derived). Do NOT use camera.up.
- Drop setTargetAtTime on listener orientation entirely, or use timeConstant 0.005 s not 0.02 s. With timeConstant 0.02s, a 180° turn takes ~60–100ms to settle and the HRTF lags the visuals — players will feel sound 'sliding' behind their view. Position can ramp (0.02s is fine); orientation should track tightly. Better: only update listener params when the camera actually moved/rotated more than an epsilon to save CPU.
- Fix occlusion routing: build ONE persistent granny chain = grannyLayerSum(GainNode) → occludeLP → occludeGain → grannyPanner → grannyBus. Route the 3 loop layers AND every granny sting's output into grannyLayerSum (not into a private panner). granny.update() drives the single occludeLP/occludeGain. Stings then automatically inherit current occlusion. This also means stings are built fresh (legal) but connect to a long-lived sum node (correct).
- Define the heartbeat intensity function explicitly and slow it WAY down. intensity = clamp01( 0.6*awareness01 + 0.4*proximity01 ), where proximity01 = clamp01((12 - dist_m)/12) (audible dread radius 12 m, max at <=2 m). Gate it: rising edge ramp timeConstant 0.4 s, FALLING edge timeConstant 2.5 s (asymmetric — fast to scare, slow to relax). Add a chase latch: while granny.state==='chase', floor intensity at 0.75 regardless of distance so breaking LOS doesn't instantly calm the music. This single change is the difference between 'tense' and 'broken.'
- Loop lifecycle: every loop voice must store its sources and, after any fade-to-0, call source.stop(ctx.currentTime + fadeSec + 0.05) so onended fires and disconnects. On granny state crossfade you keep the SAME 3 persistent loops (just re-ramp their gains) — do NOT spawn new loop voices per state, or you leak. Only stop+rebuild loops on full teardown/respawn.
- HRTF cost: cap it. Use panningModel='HRTF' for Granny's single panner ONLY; use 'equalpower' for footsteps, doors, items. Also CAP concurrent spatial one-shots (e.g. max 8 simultaneous footstep/item voices; if exceeded, skip the quietest). HRTF on ~20 transient voices on an integrated GPU/CPU laptop will spike the audio thread and cause dropouts — equalpower is ~10x cheaper and players won't localize a 60ms footstep via HRTF anyway.
- exponentialRamp guard is stated but make it a rule in code: a helper rampTo(param, value, tc) that substitutes 0 → 0.0001 and appends setValueAtTime(0, t+5*tc) when target is 0. Otherwise every hand-written ramp-to-silence is a latent InvalidStateError or stuck-at-0.0001 tail.
- DynamicsCompressor as 'brickwall limiter' with ratio 12 / threshold −6 / attack 3ms is NOT a true limiter — it will pump audibly when slam+growl+scream stack (release 250ms ducks everything for a quarter second after each transient). For a horror game that pumping is noticeable. Lower threshold to −3, raise ratio to 20, attack 1ms, release 100ms, AND keep per-sound gains conservative (sum of simultaneous worst-case ≈ slam 0.95 + growl 0.9 + heartbeat 0.7 + scream 1.0 way exceeds 1.0). Pre-scale bus gains so typical peaks sit ~−6 dBFS and the compressor only catches rare stacks.
- Add hysteresis to occlusion boolean, not just an 0.08s smooth: require the ray to report the SAME state for 2 consecutive AI ticks before flipping (or use ray hit-fraction with thresholds enter<0.4 / exit>0.6). At a doorframe the boolean will chatter every frame and 0.08s smoothing alone produces a wobbling lowpass.

### Missing Details
- Audio thread vs physics thread coupling unspecified: granny.update() reads 'the LOS raycast result the AI provides' and footsteps 'emit a hearing noise-event to the AI.' Order of operations within a frame (does audio read this-frame or last-frame raycast?) and what happens when the physics step runs at a different rate than render (cannon-es fixed timestep) is undefined. One-frame-stale occlusion is fine; using a raycast that hasn't run yet (null) is a crash.
- No pooling/voice-stealing policy with numbers despite the synthesize-and-discard model. 'Web Audio nodes are cheap' is true per-node but 6+ nodes per footstep at sprint cadence 0.34s plus item/door events means dozens of allocations/sec; GC pauses cause audio glitches. Needs a stated cap and a voice-steal rule (given above as a fix).
- Heartbeat scheduler vs ctx.suspend interaction: on visibilitychange→suspend, ctx.currentTime FREEZES while the JS look-ahead timer keeps ticking; on resume, nextBeatTime is now in the past and the scheduler dumps a burst of catch-up beats. Needs: on resume, reset nextBeatTime = ctx.currentTime + interval. Not addressed.
- No declared latency target or AudioContext({latencyHint}) choice. For footsteps to feel synced to movement and stings to land on the jumpscare frame you want latencyHint:'interactive'. Default 'balanced' adds ~tens of ms. Unspecified.
- Doppler is mentioned ('Doppler zipper') but PannerNode Doppler (dopplerFactor/speedOfSound) was REMOVED from the spec years ago and is a no-op in r184-era browsers — the 'Doppler zipper' framing is a misnomer; the real artifact is panning-position zipper. Harmless but signals the author may expect Doppler that won't exist; if Doppler pitch-shift on Granny rushing the player is wanted, it must be synthesized manually (it is not in the design).
- Stings list mismatch: publicInterface playSfx names include 'jumpscare' but granny.setState fires 'growl'/'scream'/'whimper' stings that are NOT in the playSfx name list — so the sting recipes for growl/scream/whimper are referenced but never declared as callable recipes. Needs an explicit private sting registry.
- No mention of how many total simultaneous AudioBufferSourceNodes/Oscillators the target (browser on a mid laptop) sustains, nor a measured budget. 'Cap concurrent footsteps' is hand-waved with no number until my fix.
- Procedural footstep/voice quality is acknowledged as a risk but there is no fallback or acceptance test. 'Budget time on noise-color + jitter' is not a spec. Needs a concrete acceptance bar (e.g. 'breathing layer must be the dominant idle cue at 0.5 gain; if footsteps sound synthy, add a 2nd decorrelated noise layer with 8–15ms offset and ±3 cent detune').
