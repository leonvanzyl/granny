## CRITIQUE worksProb=0.55
### Fatal flaws
- VOID-HOLE EYES WILL NOT READ AS HOLES UNDER THIS LIGHTING RIG. The design's whole face concept is 'emissive-0 black sockets = negative-space holes,' but render.js has a permanent HemisphereLight (RENDER.hemi.intensity) + AmbientLight (RENDER.ambient.intensity) that hit every fragment unconditionally — a 0x000000 / 0x050302 MeshStandardMaterial still receives ambient+hemi and renders as a flat dark-grey blob, NOT a hole. Holes only work in pure dark with a raking flashlight, and the flashlight is the ONLY shadow caster, so when the beam is OFF the sockets are lit by ambient and look like grey paint; when the beam is ON it floods INTO the shallow 0.034-radius concavity and kills the shadow. The 'risk' note admits 'void-hole needs flashlight overhang' but provides zero numbers for ambient/hemi suppression. As written this is a coin-flip on looking creepy vs. looking like a lumpy mannequin.
- FRAME-LOOP COUPLING: creepFX twitch + stillness lerp run inside animate(dt,...) which is called from update(dt,alpha) ONCE PER RENDER FRAME (granny.js:495-500), NOT in the fixed 1/60 substep. dt is the variable render delta. All the design's lerp rates (0.18, 0.86 decay, 0.25/0.12 stillness, mulberry32 twitchT+=dt) are framerate-DEPENDENT as written — at 144Hz the head twitch decays/lerps ~2.4x faster than at 60Hz, and twitchNext=1.5+rand*4 fires at the same wall-clock rate but the lerp toward it overshoots differently. On a 30fps phone the 'micro twitch' becomes a visible snap. The design treats these as if dt were fixed.
- WAIST PIN COUPLING IS UNDER-SPECIFIED AND THE RISKIEST SEAM (design admits this). waistRing is parented to 'upper' at local origin — but 'upper' has rotation.x driven 0.22→1.07 during the two-phase lunge AND root.position.y bobs AND the model root yaws to this.facing. The cloth reads waistRing.matrixWorld after model.updateMatrixWorld(true). Problem: update() sets model.position/rotation from interpolatedPos(alpha) at render time, but the LUNGE upper.rotation is set in animate() which runs AFTER position is set — so within one frame the order is position→animate→(cloth must run after). The design says 'cloth must call updateMatrixWorld(true) before reading' but does NOT pin down WHERE in main.js's loop the cloth solve happens relative to granny.update(). If cloth solves before animate() writes the lunge pose, the pin ring lags the body by a full frame during the fastest motion (lunge) — exactly when trailing artifacts are most visible.

### Concrete fixes
- FIX THE VOID EYES PROPERLY — three required, with numbers: (a) Set socket material emissive intentionally NEGATIVE-via-darkness is impossible; instead make sockets unlit-black by using MeshBasicMaterial(color 0x000000) for the void sphere so ambient/hemi never touch it (Basic ignores lights) — this is the only reliable 'hole' under a permanent ambient term. (b) Recess the void sphere deeper: scale z to 0.6 and push to z=0.050 (not 0.058) so the brow (BoxGeometry at z=0.078..0.082) physically overhangs it. (c) Keep the eye glint as the design's emissive 0xb8a886 but RAISE emissiveIntensity to 0.5 (0.22 is invisible against the existing eyeWhite 0xcabd9a at ambient); the glint is what sells it, not the hole. Verify by screenshotting with flashlight off.
- MAKE ALL creepFX RATES FRAMERATE-INDEPENDENT. Replace every fixed lerp factor with an exponential form: factor = 1 - Math.exp(-k*dt). Concretely: tilt lerp k=11 (≈0.18/frame@60), twitchAmt decay use twitchAmt *= Math.exp(-15*dt) (≈0.86@60), stillness toward-1 k=17 (≈0.25@60) / toward-0 k=7.7 (≈0.12@60). twitchT/twitchNext are already dt-accumulated so they're fine. This is non-negotiable for the 'acceptable on phone' constraint — without it the twitches look broken at 30/144Hz.
- PIN THE LOOP ORDER EXPLICITLY in main.js: the per-frame sequence must be physics.syncMeshes(alpha) → granny.update(dt,alpha) [sets root pos/yaw AND runs animate() which writes lunge/creepFX upper.rotation] → model.updateMatrixWorld(true) → cloth.solve(reads waistRing.matrixWorld) → core.render. The cloth solve MUST come AFTER granny.update so the pin ring already has the lunge pose. State this as the integration contract; do not let the implementer call cloth from inside granny.update or before it. Also: pre-warm the pin by running 2-3 cloth substeps on the first frame so the dress doesn't explode from a cold start at the waist.
- Separate the head's TWO rotation authorities to avoid the build-time -0.45 fighting creepFX/lunge. The mesh sets head.rotation.x=-0.45 at build (granny.js:115) and the gait writes head.rotation.z (166); the design's stillness path zeroes gait head.rotation.z and pushes head.rotation.x toward -0.30 — but the existing else-branch lunge-recover lerps head.rotation.x toward -0.45 (174-175). Define ONE explicit precedence each frame: lunge > stillness-stare > gait, and assign head.rotation.x/.y/.z from scratch every frame (never +=) so the baked -0.45 is a rest target only, not an additive base. The design says 'creepFX additive' which will DRIFT the head over time — make twitch additive but tilt/stare absolute.
- Tag every new face/jaw mesh to NOT cast shadows (m.castShadow=false) before the traverse at granny.js:147, or set the traverse to skip them. 9 new sub-1cm meshes (eyes/pupils/sockets/lip/cavity) casting into the single 2048 shadow map add cost and produce shadow-acne speckle at that scale (shadow.bias -0.0008 is tuned for furniture, not 0.005-radius pupils). They receive shadow fine; they should not cast.

### Cut scope
If perf or time is tight, cut in this order: (1) Drop the slack-jaw jawJoint entirely (static mouth) on ALL platforms, not just mobile — animated jaw during lunge is the lowest-value, highest-coupling-risk element (it adds a 4th rotation authority and 3 meshes for a detail seen for ~0.3s during a jumpscare). (2) Cut the per-eye glint emissive animation; static emissiveIntensity 0.5 is enough. (3) Cut the random head-twitch (twitchAmt/tiltTarget mulberry path) and keep ONLY the stillness freeze-stare — the freeze-stare is the high-value 'P.T.' beat; the twitch is non-deterministic polish that the design itself flags as risky. KEEP: the recessed MeshBasicMaterial void eyes (the core 'wrong' read), the two-phase lunge (gameplay-readable telegraph), and the waistRing (cloth depends on it — but if cloth is also cut, parent the existing LatheGeometry skirt to waistRing instead of root, which is a 1-line change and the design's own fallback).
