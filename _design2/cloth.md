# COMPONENT: cloth

## Summary
A new module src/cloth.js exports buildClothDress({ material, mobile }) returning { group, update(waistMatrix, dt) }. It simulates a cylindrical skirt as a Verlet particle grid: COLS=16 columns x ROWS=10 rows (160 particles), top row PINNED to a waist ring derived each frame from Granny's animated `upper` group world matrix. Verlet integration with gravity, velocity damping and a cheap value-noise wind/sway. Constraints: structural (vertical+horizontal) + shear (diagonal) + bend (skip-1), solved with 6 Gauss-Seidel iterations. Collision against 5 moving spheres approximating hips + both thighs + both shins, pushed out positionally. A double-sided BufferGeometry (front + duplicated back-facing triangles, or a single double-sided material) is rewritten from particle positions every render frame with recomputed normals. It runs INSIDE granny.update, AFTER this.animate(...) so it consumes the exact same animated waist pose (no 1-frame lag), once per render frame (decoupled from the 1/60 physics substeps). dt is clamped to 1/30 and the solver sub-steps to stay stable on a big frame. Mobile (Touch.init()===true) keeps the existing rigid Lathe skirt and never instantiates the sim.

## Key decisions
- Module boundary: new file src/cloth.js, zero new deps (cannon-es untouched — cloth is a separate kinematic-only sim that never enters the physics world). granny.js imports buildClothDress and chooses cloth vs lathe by a `mobile` flag passed into buildGrannyModel.
- Pin to the animated waist, not the body root: the skirt top ring must follow `upper` (which leans 0.5 rad + sways + lunges). granny.update already calls this.animate(...) which sets upper.rotation; immediately after, we read upper.matrixWorld (force-updated) and pass it as waistMatrix. The cloth group itself is added to `root` at identity so cloth particles live in root-local space; we transform the waist ring into root-local space using root.matrixWorld^-1 * upper.matrixWorld, computed once per frame.
- Verlet over springs-with-forces: position-based Verlet (x += (x - xPrev)*damp + a*dt^2) is unconditionally stable for stiff cloth at low iteration counts, unlike explicit spring forces which explode. Constraints are solved positionally so stiffness is just iteration count, no spring-k tuning that can blow up.
- Cylinder topology is a SEAM-CLOSED grid: column 0 and column COLS-1 are the same ring position (we wrap horizontal/shear/bend constraints modulo COLS) so there is no visible split seam. The mesh duplicates the seam column's vertices for UV continuity but shares particle indices via modulo.
- Double-sided via material.side=THREE.DoubleSide on a single MeshStandardMaterial (cheaper than building back faces manually) — the cloth is thin and we recompute normals each frame, so DoubleSide with proper normals reads correctly from inside and outside.
- Collision spheres are derived from the SAME joint groups (legL/legR hip/knee, upper) so they move with the gait; the dress reacts to the legs walking through it. Spheres are positional-only constraints (no impulse), matching Verlet.

## Data model
Flat typed arrays for cache efficiency, N = COLS*ROWS = 160 (desktop). pos: Float32Array(N*3) current positions (root-local space). prev: Float32Array(N*3) previous positions. tmp: Float32Array(N*3) scratch. pinned: only row 0 (indices 0..COLS-1) — stored implicitly (idx < COLS). Index helper: idx(c,r) = r*COLS + c; wrapCol(c) = (c+COLS)%COLS. Constraints precomputed once into a Uint16Array of [i,j] pairs plus a parallel Float32Array of rest lengths: structural-vertical (c, r)-(c, r+1), structural-horiz (c,r)-(wrap(c+1),r), shear (c,r)-(wrap(c+1),r+1) and (wrap(c+1),r)-(c,r+1), bend-vertical (c,r)-(c,r+2), bend-horiz (c,r)-(wrap(c+2),r). Rest lengths captured from the initial rest pose (a truncated cone: top radius 0.15 at waist y, bottom radius 0.23 at hem, hem length ~0.62 m so it drapes to mid-calf). Render mesh: BufferGeometry with position attribute of size (COLS+1)*ROWS*3 (extra seam column for UVs), a precomputed index buffer of 2*COLS*(ROWS-1) triangles, normal attribute (recomputed), uv attribute (static: u = c/COLS, v = r/(ROWS-1)). Collision spheres: array of 5 {center:Vec3 (root-local), radius}. Waist ring: COLS sample points around a circle of radius 0.15 in `upper`-local space at the skirt-top y, transformed to root-local each frame via a cached Matrix4.

## Algorithms
- FRAME STEP (cloth.update(joints, dt)): 1) compute root-local waist ring + collision spheres from joint world matrices; 2) move pinned row-0 particles to the new ring positions (this drags the cloth); 3) Verlet integrate rows 1..ROWS-1; 4) solve constraints ITER times; 5) resolve sphere collisions; 6) write BufferGeometry positions + normals.
- WAIST FOLLOW: invMat.copy(joints.root.matrixWorld).invert(); waistLocal.multiplyMatrices(invMat, joints.upper.matrixWorld). For c in 0..COLS-1: localPt = (cos(theta)*topRadius, skirtTopY_in_upperLocal, sin(theta)*topRadius) where theta=2*pi*c/COLS; ringPt = localPt.applyMatrix4(waistLocal); pos[idx(c,0)] = ringPt (hard set, also set prev=pos for pinned so they impart no spurious velocity except the real ring motion which Verlet picks up from neighbors).
- VERLET (per free particle i, components): vx = (pos - prev)*DAMP; prev = pos; pos += vx + accel*dt2 where dt2=dt*dt. accel = (0,GRAVITY,0) + wind. DAMP=0.97. GRAVITY=-9.0 (gentler than physics gravity for a draping look). WIND: w = WIND_AMP * noise(t*0.6 + r*0.3, c*0.2) applied mostly tangentially + a slow global sway sin(t*0.8)*0.15; WIND_AMP ramps with granny moveSpeed (passed in) so the dress trails when she walks/lunges. Gust on lunge: add forward kick along upper's -Z.
- CONSTRAINT SOLVE (Gauss-Seidel, ITER=6 desktop / would-be 3 mobile but mobile uses lathe): for each [i,j],rest: d = pos[j]-pos[i]; len=|d|; if len<1e-6 continue; diff=(len-rest)/len; corr=d*0.5*diff*STIFF; if i pinned: pos[j]-=corr*2 (full correction to free side); elif j pinned: pos[i]+=corr*2; else { pos[i]+=corr; pos[j]-=corr; }. STIFF=1.0 for structural, 0.9 shear, 0.6 bend so the skirt holds its conical shape but folds softly. Constraint ordering: structural first, then shear, then bend, repeated each of the 6 iterations.
- SPHERE COLLISION (after constraints, 1 pass): for each free particle, for each sphere s: d = pos - s.center; len=|d|; if len < s.radius { pos = s.center + d*(s.radius/len) }. If len~0 push along +radial outward. Apply a small tangential friction by also nudging prev toward pos (prev = lerp(prev,pos,0.3)) so cloth doesn't slide frictionlessly off legs. Spheres: hips r=0.20 at upper origin; left/right thigh r=0.12 at legL/legR hip+(-0.15y); left/right shin r=0.09 at knee. All in root-local space.
- NORMALS + MESH WRITE: copy the COLS particle columns into the (COLS+1)-wide vertex buffer (duplicate column 0 into column COLS for the UV seam). geometry.attributes.position.needsUpdate=true. Recompute normals cheaply per-vertex via cross product of (right-left) x (down-up) finite differences over the grid (O(N), avoids geometry.computeVertexNormals overhead of indexed dedup) — yields correct double-sided lighting. normal.needsUpdate=true. Skip computeBoundingSphere except every 20th frame (or set a fixed generous bounding sphere radius 1.0 at waist center) so frustum culling never hides the dress.

## Tunables
- COLS=16, ROWS=10  -> N=160 particles, ~150 triangles (desktop budget; trivial vs scene)
- ITER=6 constraint iterations per frame
- STIFF_STRUCT=1.0, STIFF_SHEAR=0.9, STIFF_BEND=0.6
- DAMP=0.97 (velocity retention; lower = more air drag)
- GRAVITY=-9.0 m/s^2 (artistic, < physics -18 for slower drape)
- dtClamp = min(dt, 1/30); if dt>1/45 split into 2 verlet sub-integrations to avoid stretch on a hitch
- WIND_AMP=0.35 base + moveSpeed*0.25; sway freq 0.8 Hz; lunge gust +0.6 along -Z for 0.25 s
- Geometry: waistY=0.94, topRadius=0.15, hemRadius=0.23, hemY=0.32 (hem ~0.62 m tall, ends mid-calf so stocking legs still show)
- Collision radii: hips=0.20, thigh=0.12, shin=0.09; friction lerp=0.3
- boundingSphere recompute interval=20 frames (or static r=1.0)
- MAX_STRETCH clamp: after solve, if any structural spring > 1.5*rest, hard-clamp particle toward neighbor (anti-explosion safety net)

## Mobile fallback
Detected via Touch.init() (MOBILE in main.js, already computed before Granny is built). Pass MOBILE into Granny -> buildGrannyModel(mobile). When mobile===true: take the EXISTING code path verbatim (the current LatheGeometry skirt + fold creases + apron, lines 53-67), set cloth=null, and granny.update's `if (this.cloth)` block is skipped entirely — zero per-frame cost, identical to today's behavior. No Verlet arrays are allocated. The rigid lathe already sways slightly via root bob/upper.rotation.z since it's parented to root, which is acceptable on phones. Optionally, a 'medium' tier could run COLS=10/ROWS=6/ITER=3, but the hard requirement is: phone == rigid lathe. The desktop dress also auto-degrades on a big dt via dtClamp, so a desktop frame spike never explodes the sim.

## Pitfalls
- Using upper.matrixWorld before it is updated: Three only refreshes matrixWorld during render or via updateWorldMatrix. Must call joints.root.updateWorldMatrix(true,true) inside granny.update AFTER this.animate set the rotations and BEFORE cloth.update — otherwise the waist ring lags one frame and the pin 'rubber-bands'.
- Pinning by overwriting prev=pos every frame KILLS the ring's own velocity transfer; instead set pos for pinned row but let the FIRST free row pick up motion through the structural constraints. Do not zero prev of free rows.
- Recomputing normals with geometry.computeVertexNormals() each frame on an indexed buffer is slower and can flip on the seam; use the manual finite-difference normal pass over the grid.
- Forgetting the horizontal seam wrap (modulo COLS) leaves a visible vertical split where the cylinder closes; constraints AND the duplicated-seam vertex copy both must handle wrap.
- DoubleSide without correct normals makes the inside of the skirt self-shadow black; ensure normals point consistently outward (cross-product order) and that the ONE shadow-casting flashlight SpotLight still lights it — cloth.group meshes need castShadow=true & receiveShadow=true like the rest of the model (set in the root.traverse at line 147, so add cloth.group BEFORE that traverse, or set flags inside buildClothDress).
- Collision spheres computed from interpolated vs simulated body pose mismatch: the model is placed at alpha-interpolated body pos in granny.update (line 497) while joints animate off dt — keep spheres in root-LOCAL space (derived from joint local/world transforms relative to root) so the whole-body translation/rotation is automatically handled by parenting; never mix world body pos with local particle space.
- dt of 0 on the very first frame (or after pause/resume) -> dt2=0, particles freeze that frame (harmless) but a huge dt after resume would over-stretch: dtClamp handles it; also reset prev=pos on Granny.reset() to avoid a launch when teleporting between days.
- Bounding sphere: if you let computeBoundingSphere run on a degenerate first frame (all verts at origin) the dress may be culled; set a static bounding sphere or recompute after the first real update.

## CRITIQUE worksProb=0.62
### Fatal flaws
- FRAMERATE-DEPENDENT DRAPE (the real bug, not perf). The solver is run once per RENDER frame with dt=actual frame time, but DAMP=0.97, GRAVITY=-9, WIND, and especially ITER=6 are all implicitly tuned for ~16.7ms. The design even admits this in risks ('144Hz -> stiffer/less lively') then dismisses it. It is worse than admitted: position-based Verlet stiffness is a function of (iterations per second), not per frame. At 144Hz you get 864 constraint passes/sec -> a rigid board; at 40Hz you get 240 -> a stretchy rag that visibly sags differently. The 'optional fixed 1/60 accumulator' the design waves away is NOT optional — it is the only thing that makes the dress look the same on every machine. Shipping per-render-frame means QA on a 60Hz dev box and shipped-broken on every 120/144Hz laptop and every phone-that-isn't-using-the-fallback.
- PIN HANDSHAKE IS UNDER-SPECIFIED AND WILL RUBBER-BAND. The design correctly identifies that upper.matrixWorld is stale (confirmed: granny.update sets model.position THEN calls animate() which only sets .rotation — matrixWorld is never refreshed until render). Its fix is `joints.root.updateWorldMatrix(true,true)`. But root IS this.model, whose .position was set THIS frame to the ALPHA-INTERPOLATED body pos (line 497), while the joint rotations come from animate() driven by raw dt (line 500). The waist ring is therefore built from an interpolated translation + a dt-driven rotation — internally consistent in ROOT-LOCAL space (good, the design's instinct to stay root-local is right), but the pinned row is HARD-SET each frame to the ring while prev is also overwritten ('set prev=pos for pinned'). That kills the velocity the free rows need to feel a lunge whip. The design contradicts itself: keyDecision says drag comes from ring motion, but pitfall #2 says do NOT overwrite prev. One of these is wrong in the code that gets written. As specified it will produce a dead, non-trailing skirt OR a twitchy one depending on which sentence the implementer follows.
- DOUBLESIDE + ONE SHADOW-CASTER = BLACK INTERIOR / SHADOW ACNE. There is exactly ONE shadow light (the flashlight SpotLight, shadow.bias=-0.0008, normalBias=0.04). A thin DoubleSide cloth with per-frame finite-difference normals and castShadow=true WILL self-shadow: back faces shadow front faces from the same light. shadowSide is mentioned once in risks as a 'may need' — it is a CERTAINTY here, must be material.shadowSide=THREE.DoubleSide AND likely castShadow=false on the dress (a flapping skirt casting a 1024/2048 shadow that flickers every frame as normals recompute is both a perf cost and an ugliness source). The design's own line 'add cloth.group BEFORE the root.traverse so castShadow=true gets set' actively creates this bug.
- buildGrannyModel REFACTOR IS HAND-WAVED AT THE EXACT FORK THAT MATTERS. Current code: buildGrannyModel() takes no args, builds the lathe unconditionally, returns {group,update}. The design says 'DELETE lines 53-65' for desktop but 'mobile uses lathe verbatim'. That is a runtime branch inside one function, but the design never writes it — it says 'existing code path' as if it's free. The lathe block also builds fold creases (62-65) and the apron (67) that are entangled. Getting this fork wrong means either the lathe renders UNDER the cloth on desktop (z-fighting / double skirt) or the apron disappears on mobile. Probability the implementer leaves the lathe in on desktop and ships two overlapping skirts: high.

### Concrete fixes
- FIXED-STEP THE CLOTH. Run an internal accumulator at 1/60 inside cloth.update(joints, dt): accumulate += min(dt,1/30); while(accumulate>=H){ verlet+constraints+collide(H); accumulate-=H; } with H=1/60. Pin-ring interpolation: lerp the pinned row from its previous ring to the current ring across the substeps so a 16ms frame with 1 substep and a 33ms frame with 2 substeps drag identically. This removes the entire 'framerate-dependent drape' class of bug for ~2x worst-case solver cost — still <0.4ms. Do NOT ship per-render-frame; it is the single highest-value change.
- PIN VELOCITY: set pos[pinned]=ring each substep but set prev[pinned]=PREVIOUS ring position (not =pos). That makes the pinned row carry the true ring velocity into the structural springs, which is what produces trailing/whip. Only reset prev=pos on Granny.reset()/teleport. Resolve the self-contradiction in the spec in favor of this.
- SHADOWS: dress mesh castShadow=FALSE, receiveShadow=TRUE, material.shadowSide=THREE.DoubleSide (harmless given no cast), and set these flags INSIDE buildClothDress AFTER adding to root, OR add cloth.group AFTER the root.traverse at line 147 and set flags explicitly — do not let the blanket traverse set castShadow=true. Saves shadow-map churn and kills the black interior.
- WRITE THE FORK EXPLICITLY: refactor to `function buildGrannyModel(mobile){ ... legs/feet/upper/head always ...; let cloth=null; if(mobile){ <lathe+folds+apron block 54-67> } else { cloth=buildClothDress(...); root.add(cloth.group); /* set shadow flags here */ } ... return {group:root, update, cloth, joints:{legL,legR,upper,root}}; }`. On desktop the lathe must NOT exist. Apron: parent it to `upper` in BOTH paths so it sways and so removing the lathe doesn't delete it. Pass mobile from main.js line 82 and store this._mobile BEFORE the model build in the constructor (currently buildGrannyModel is called at line 189 with no arg).
- NORMALS: do the manual finite-difference grid normal pass as specified (computeVertexNormals on indexed buffer every frame is genuinely slower and seams flip) — but FIX the seam: the duplicated UV-seam column (col COLS) must copy normal AND position from col 0 every frame, AND the modulo-wrapped horizontal/shear/bend constraints must use wrapCol so col0 and col(COLS-1) are neighbors. If only the constraints wrap but the normal of the seam vertex is computed one-sided, you get a visible lit crease, not a split. Spell out both.
- RESET HANDLING IS MANDATORY, NOT OPTIONAL: Granny.reset() (line 219) teleports the body across the house between days; doRespawn calls it. Add cloth.reset(joints) that recomputes the ring and sets pos=prev=ring-draped rest pose, called from Granny.reset(). Without it the dress streaks across the room for several frames on every respawn (5x per run minimum). The design lists this in pitfalls but does not put it in the integration steps — make it a step.
- COLLISION DURING LUNGE: lungeTime is only 0.35s at lungeSpeed 4.5 — that is a fast pose change. 5 coarse spheres WILL let a fold poke through the gap between thigh(r=0.12) and shin(r=0.09). Either overlap them (place shin sphere high enough that thigh+shin surfaces touch) AND run the sphere pass twice when lungeT>0 (cheap, ~800 ops), or accept it and CUT visual fidelity by raising hemY so the hem clears the knees. Pick one in code; don't leave it as a 'mitigation' bullet.
- BOUNDING SPHERE: set geometry.boundingSphere to a static new THREE.Sphere(center=(0,0.6,0) in root-local, radius=1.0) ONCE at build and never recompute. The 'every 20th frame' option risks a cull on the degenerate first frame. Static is free and correct because the dress can't exceed hem length from the waist.

### Cut scope
"If perf or time is tight, CUT the cloth sim entirely on a tier and ship the rigid lathe to everyone but high-end desktop — the design already proves the lathe path is zero-cost and acceptable. Specifically: (1) Drop bend constraints (keep structural+shear) and ITER 6->4: the conical skirt still holds shape, saves ~40% solver, removes the softest-to-tune springs. (2) Drop the per-frame normal recompute to every-other-frame (lighting on a slow-draping cloth tolerates 30Hz normals) before you ever touch particle count. (3) If still over budget, COLS 16->12, ROWS 10->8 (96 particles) — the hem detail loss is minor at Granny's typical screen size in a dark foggy scene. Do NOT cut the fixed-step accumulator or the shadowSide fix to save time — those are correctness/ugliness, not perf, and cost almost nothing. The honest fallback if cloth proves flaky in integration is: rigid lathe + a cheap fake — parent the lathe to `upper` and add a 1-bone sinusoidal hem sway driven by moveSpeed. It reads as 'sways/drags' from a distance in fog for ~zero risk, and is the right thing to ship if the Verlet handshake fights the alpha-interpolated root."
